# wl2028rating

校内训练比赛的 Rating 与奖牌统计页面。

## 项目结构

```text
.
├─ index.html          # 页面骨架
├─ styles.css          # 页面样式
├─ app.js              # Rating / 休眠 / 奖牌计算与渲染
├─ data/
│  └─ ratings.csv      # 唯一历史成绩数据源
└─ tools/
   └─ update.py        # 追加新比赛的辅助脚本
```

以后日常更新原则上只需要修改 `data/ratings.csv`。网页会在打开时自动读取该文件并重新计算所有 Rating、休眠状态、比赛强度和奖牌。

## ratings.csv 格式

第一列是选手 ID，后续每一列是一场比赛。

- `12`：本场排名 12，且该选手视为独立的一人队。
- `3-队伍名`：排名 3，且属于同名队伍；同一队伍成员使用相同队伍名。
- `-1`：当时已经存在的选手缺席本场。
- `0`：该选手在这场比赛时尚未加入统计系统（通常只出现在新选手的历史列）。

所有数据行必须与表头列数完全一致。

## 添加一场新比赛

准备一个结果文本，例如 `results.txt`：

```text
Jian132363 1
Mooos 2-uwu
yrjzs 3-佬佬菜菜带带
```

然后执行：

```bash
python tools/update.py 2026.09.16 results.txt
```

脚本会：

1. 检查比赛名是否重复；
2. 检查 CSV 每行列数；
3. 给未参赛的老选手追加 `-1`；
4. 给新选手的全部历史比赛补 `0`；
5. 对疑似拼错的 ID 给出旧 ID 候选并默认停止；
6. 写入前保留 `data/ratings.csv.bak` 备份；
7. 输出参赛人数、参赛队伍数、新选手和冠军摘要。

确认疑似相似 ID 确实是新选手时，可使用 `--allow-new`。只想检查而不写入时使用 `--dry-run`。

## 奖牌规则

单场只计最高的一档，优先级为：

```text
金冠 > 银冠 > 金牌 > 银牌 > 铜牌
```

所有奖牌比例都按 **实际参赛队伍数** `n` 计算，而不是参赛人数。同一队伍的多个成员只算 1 支队伍，但该队获得的奖项会记给所有成员。

- 冠军获得皇冠，不再同时获得普通金牌；
- 非冠军排名位于前 `ceil(n × 10%)`：金牌；
- 再到前 `ceil(n × 30%)`：银牌；
- 再到前 `ceil(n × 60%)`：铜牌；
- 所有冠军至少获得银冠，满足下面的“高强度争冠局”条件时升级为金冠。

### 金冠：争冠强度

金冠不按参赛人数或固定 Rating 判断，而是衡量冠军实际击败的争冠集团强度。计算只使用 **该场比赛开始前的 Rating**，不会改变 Rating 系统本身的 team rating 逻辑。

每支队伍的原始实力为：

```text
R_team = 800 * log10(sum(10^(Ri / 800)))
```

其中 `Ri` 是队内成员的赛前 Rating。组队本身带来的实力增益会保留。

为了避免“全场普遍组队”让不同比赛之间的强度整体虚高，每场先计算公共组队增益：

```text
commonTeamBonus = median(800 * log10(teamSize))
```

这里遍历本场所有参赛队伍。随后所有队伍统一使用：

```text
adjustedTeamRating = rawTeamRating - commonTeamBonus
```

作为金冠强度计算用的实力。因为全场减去的是同一个值，所以同场队伍之间的相对强弱不变；少数队伍组队时的优势也仍然保留。

计算单场 `competitionStrength` 时，先排除最终冠军队，再按 `adjustedTeamRating` 从高到低取最多 5 支最强竞争队，按 `5:4:3:2:1` 加权平均：

```text
competitionStrength =
(5*R1 + 4*R2 + 3*R3 + 2*R4 + R5) / 15
```

如果不足 5 支竞争队，只使用实际存在的队伍和对应的前几个权重，并把分母改为实际权重之和。例如只有 3 支竞争队时使用 `(5*R1 + 4*R2 + 3*R3) / 12`。

### 金冠动态门槛

金冠门槛使用 20 场参考窗口中的 **第 3 高争冠强度**，即 20 场里的前 15%。

- **第 1～20 场**：先算出前 20 场各自的 `competitionStrength`，统一使用这 20 场中的第 3 高值作为门槛。这一段有意允许向前看第 1～20 场。
- **第 21 场开始**：第 `i` 场只看此前最近 20 场，即第 `i-20` ～ `i-1` 场，取其中第 3 高值作为当前门槛。当前比赛本身不会进入自己的参考窗口。
- 当前比赛满足 `competitionStrength >= goldCrownThreshold` 时为金冠局，否则冠军获得银冠。
- 未来比赛不会重新评判已经结束的比赛，因此过去已经获得的金冠不会被后来的强比赛刷掉。

Rating 主表的每场比赛表头会显示争冠强度；金冠局会额外显示 `👑` 并使用轻微的金色列强调。表头 tooltip 还会显示当场的金冠门槛。

主榜名字旁只显示该选手历史最高级别的 **金冠 / 银冠 / 金牌** 标志；银牌、铜牌只在奖牌榜统计。

奖牌榜按金冠、银冠、金牌、银牌、铜牌数量依次降序排序；完全相同后按当前 Rating、ID 排序。

## 本地预览

页面通过 `fetch()` 读取 `data/ratings.csv`，因此不要直接双击 `index.html`。在仓库根目录启动一个本地 HTTP 服务，例如：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。GitHub Pages 环境可直接使用。
